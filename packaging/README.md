# Packaging (macOS)

The app bundle comes from `WhatsRusty.xcodeproj`, generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen)
from `project.yml` (`brew install xcodegen`, then `xcodegen generate` after editing `project.yml`; the
generated project is committed so CI builds it as is). Its build phase runs
`xcode-cargo-build.sh`, which builds the cargo workspace for arm64 and installs the binary as
`Contents/MacOS/WhatsRusty`. Releases are built, notarized and published by `publish.sh`, in GitHub Actions or on a Mac; see
[CI.md](../CI.md) and [SIGNING.md](../SIGNING.md).

| File | Purpose |
| --- | --- |
| `Info.plist` | Bundle keys, microphone usage text, Sparkle feed/public key (`SU*`) |
| `entitlements.plist` | Hardened-runtime entitlements (network client, audio input; no sandbox, see the comment inside) |
| `Signing.xcconfig` | Automatic Apple Development signing; optionally includes an uncommitted `Local.xcconfig` |
| `xcode-cargo-build.sh` | Xcode build phase: `cargo build` (`--release` for Release) → bundle executable |
| `Sparkle/` | Swift package pinning the Sparkle 2.10.0 binary release by SHA-256 checksum |
| `icon/AppIcon.icon` | Icon Composer document, compiled by `actool` into `Assets.car` + `AppIcon.icns` (`icon/make-icon-composer.py` regenerates it) |
| `build-app.sh` | Ad-hoc signed Debug (`WhatsRusty Dev.app`) or `--release` bundle in `build/app` |
| `release.sh` | Developer ID release build: archive → export → verify → notarize + staple → ZIP + DMG |
| `publish.sh` | Release a tag: clean-worktree build via `release.sh`, Sparkle signing, GitHub Release + feed |
| `rust-toolchain` | Rust version used by CI and releases |

## Configurations

| | Debug | Release |
| --- | --- | --- |
| App | `WhatsRusty Dev.app` | `WhatsRusty.app` |
| Bundle id | `me.balaj.WhatsRusty.dev` | `me.balaj.WhatsRusty` |
| Data | `~/Library/Application Support/WhatsRustyDev` | `~/Library/Application Support/WhatsRusty` |
| Logs | `~/Library/Logs/WhatsRustyDev` | `~/Library/Logs/WhatsRusty` |
| Sparkle | off | on |

`cargo run` builds are Debug builds. On first launch a Release build renames the old
`~/Library/Application Support/WhatsApp GPUI` and `~/Library/Logs/WhatsApp GPUI` folders to the new
names if the new ones don't exist yet (never in `WA_MOCK` mode). Debug builds start empty.

## Local bundle

```sh
packaging/build-app.sh             # Debug, ad-hoc signed
packaging/build-app.sh --release   # Release, ad-hoc signed
# Mock data from the Release bundle, with a throwaway HOME so no real folders are created or moved:
HOME=$(mktemp -d) WA_MOCK=1 "build/app/Build/Products/Release/WhatsRusty.app/Contents/MacOS/WhatsRusty"
```

Env vars don't pass through `open`, so run the executable directly for mock mode.

## Local Developer ID release

Needs a `Developer ID Application` certificate for team W7TT249CUU in the login Keychain and,
for notarization, a notarytool profile (once):

```sh
xcrun notarytool store-credentials WhatsRusty \
  --key ~/path/AuthKey_<KEYID>.p8 --key-id "<KEYID>" --issuer "<issuer UUID>"
```

```sh
packaging/release.sh                 # → dist/WhatsRusty-<version>.dmg and dist/WhatsRusty-<version>-<build>.zip
packaging/release.sh --no-notarize   # sign + verify + package only
```

Env overrides: `SIGN_IDENTITY`, `NOTARY_PROFILE` (default `WhatsRusty`), `BUILD_NUMBER`
(`CFBundleVersion`), `CARGO_TARGET_DIR`. The script never publishes anything; the public update
feed only comes from the CI pipeline.

## Notes

- Running from a bundle is what enables system notifications (`UNUserNotificationCenter` needs a
  bundle identifier), Launch at Login (`SMAppService`) and Sparkle; `cargo run` builds skip them.
- Hardened runtime blocks the microphone unless `com.apple.security.device.audio-input` is present
  *and* `NSMicrophoneUsageDescription` is in Info.plist; both are set.
